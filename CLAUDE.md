# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`sruedadev` is a Django site for sruedadev.com, a freelance web/software dev business. There's no CMS and no content models — nearly all page content (services, pricing, portfolio, FAQ, testimonials) lives as Python dicts in `core/data.py`, which views and the `site_globals` context processor read directly.

## Commands

```bash
python -m venv env
env\Scripts\activate          # Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver    # http://127.0.0.1:8000/
```

- `python manage.py check` — validate config without running the server.
- `python manage.py collectstatic` — copy CSS/JS/images to `staticfiles/`; only needed in production.
- No automated test suite exists yet (`core/tests.py` is the stock Django stub) and there is no JS/CSS build step for the main site — `core/static/core/css/estilo.css` and `main.js` are edited directly and served as-is.
- `scripts/build-assets.sh` regenerates **minified** copies (`estilo.min.css`, `main.min.js`) via `npx esbuild` — run it after editing `estilo.css`/`main.js` and commit the `.min.*` output alongside the source change. `base.html` serves the minified files.
- `.env` (copy from `.env.example`) sets `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `GA_MEASUREMENT_ID` for production; without it, `settings.py` falls back to insecure local-dev defaults. Never commit `.env`.

## Architecture

### Content flow: `data.py` → views → templates

- `core/data.py` is the single source of truth for site content: `SERVICIOS`, `PLANES` (service detail pages), `PROCESO`, `CATEGORIAS_PORTAFOLIO`, `PROYECTOS` (portfolio items), `FAQ`, `TESTIMONIOS`, `CLIENTES`, etc.
- `core/context_processors.py` (`site_globals`) injects `servicios`, `whatsapp_numero`/`whatsapp_texto`, and `ga_measurement_id` into every template (navbar/footer/floating widgets depend on these).
- `core/views.py` builds per-page context from `data.py` and renders templates in `core/templates/core/`. Dynamic pages (`portafolio_categoria`, `portafolio_detalle`, `servicio_detalle`, `portafolio_caso`) are looked up by slug against dicts keyed from `data.py` (`PROYECTOS_POR_SLUG`, `PLANES_POR_SLUG`, `CATEGORIAS_POR_SLUG`).
- `sitemap.xml` and `robots.txt` are generated by hand in `views.py` from the same `data.py` lists (not Django's sitemap framework), so they can't drift from what's actually routed. `DOMINIO` (`https://sruedadev.com`) is hardcoded there for absolute URLs, independent of `request.get_host()`.
- The homepage (`index.html`) is composed of independent partials in `core/templates/core/partials/_*.html` (hero, servicios, proceso, portafolio, planes, testimonios, FAQ, contacto, CTA, footer, navbar, floating widgets).

### Three different ways a portfolio project is served

Each entry in `data.PROYECTOS` has a `categoria_slug` and is served one of three ways, dispatched in `views._url_proyecto()` / `views.portafolio_detalle()`:

1. **Default** — a single static HTML file in `core/portafolio_pages/<slug>.html`, read from disk and returned raw via `portafolio_detalle`.
2. **`sitio_estatico: True`** — a full multi-page static site (own CSS/JS/images) under `core/static/core/portafolio_sitios/<slug>/`, served directly as static files; `portafolio_detalle` just redirects there.
3. **`caso_estudio: True`** — no public site yet; rendered via the `portafolio_caso` view/template instead of a static file.

When adding a portfolio entry, decide which of these three it is before wiring it into `data.py` — the view logic branches on these two flags, not on inspecting the filesystem.

### `Fw_ paginas web/` — design drafts, not part of the Django site

Sibling directory with its own `CLAUDE.md`: standalone HTML landing-page mockups (one aesthetic/industry each) plus a few multi-page "showroom" concept sites (e.g. `construccion/`, `easypark/`, `inmobiliaria/`) with their own READMEs. These are design references that sometimes graduate into `core/portafolio_sitios/` or `core/portafolio_pages/` once adopted — editing them has no effect on the live site. Read the nested `CLAUDE.md` before working in that directory.

### Editing content vs. editing code

- Text, prices, services, FAQ, testimonials, portfolio entries: `core/data.py` only.
- Contact info (email, WhatsApp number/message, hours, location): `core/data.py` (`WHATSAPP_NUMERO`, `WHATSAPP_TEXTO`) plus the `_contacto.html`/`_footer.html` partials.
- Colors/typography: CSS custom properties at the top of `core/static/core/css/estilo.css` (`:root`); see `PALETA-COLORES.md` for the current token table.
- After any `estilo.css`/`main.js` change, re-run `scripts/build-assets.sh` so the served `.min.*` files stay in sync.
