# PROMPT 20 — AUDITORÍA FINAL DEL E-COMMERCE

Actúa como un equipo de QA, frontend senior, especialista en rendimiento y director creativo.

Audita el proyecto ESSENCE & TIME completo. No te limites a generar un informe: corrige los problemas encontrados.

## 1. AUDITORÍA VISUAL

Revisa todas las páginas en:

- Móvil de 360 px.
- Móvil de 390 px.
- Tablet.
- Portátil.
- Escritorio de 1440 px.

Busca:

- Desbordamiento horizontal.
- Titulares mal ajustados.
- Fotografías deformadas.
- Espacios inconsistentes.
- Botones demasiado pequeños.
- Contrastes insuficientes.
- Header excesivamente alto.
- Tarjetas desalineadas.
- Elementos que desaparecen en móvil.
- Modales que no caben en pantalla.
- Textos cortados.
- Saltos de diseño.

Si dispones de herramientas de navegador, úsalas para comprobar visualmente las páginas y tomar capturas de pantalla.

No afirmes que has ejecutado pruebas visuales si no tienes herramientas disponibles para realizarlas.

## 2. AUDITORÍA FUNCIONAL

Prueba:

- Navegación.
- Mega menú.
- Menú móvil.
- Buscador.
- Filtros.
- Ordenamiento.
- Paginación.
- Detalle del producto.
- Galería.
- Variantes.
- Favoritos.
- Carrito.
- Modificación de cantidades.
- Cupones.
- Checkout de demostración.
- Confirmación.
- Formularios.
- FAQ.
- Estados vacíos.

Verifica que todos los controles hagan lo que anuncian.

## 3. AUDITORÍA TÉCNICA

Comprueba:

- Errores JavaScript.
- Rutas de archivos.
- Enlaces rotos.
- Imágenes que no cargan.
- Scripts duplicados.
- Event listeners duplicados.
- Problemas de localStorage.
- Errores de cálculo.
- Accesibilidad básica.
- Uso correcto de semántica HTML.
- Metadatos SEO.
- Recursos innecesarios.
- Compatibilidad con prefers-reduced-motion.

## 4. AUDITORÍA DE ANIMACIONES

Revisa cada animación GSAP.

Elimina movimientos excesivos, retrasos que dificulten la compra y efectos que afecten el rendimiento.

Verifica que la página siga siendo utilizable con movimiento reducido.

## 5. AUDITORÍA COMERCIAL

Comprueba que:

- Los precios sean consistentes.
- Los descuentos se calculen correctamente.
- No se inventen existencias.
- No se inventen valoraciones.
- Los productos conceptuales estén identificados.
- No se simulen pagos reales.
- No se publiquen políticas sin validar.
- Los datos comerciales sean configurables.

## 6. ENTREGA

Corrige los errores encontrados.

Actualiza el README con:

- Requisitos.
- Cómo ejecutar el proyecto localmente.
- Estructura de archivos.
- Bibliotecas utilizadas.
- Cómo añadir productos.
- Cómo cambiar las imágenes.
- Cómo modificar precios.
- Cómo cambiar la identidad visual.
- Limitaciones de la versión frontend.
- Pasos necesarios para convertir la demostración en una tienda real.

Al finalizar, presenta un informe breve que indique:

1. Archivos revisados.
2. Errores encontrados.
3. Correcciones realizadas.
4. Pruebas ejecutadas.
5. Pruebas que no pudieron ejecutarse.
6. Pendientes antes de publicar.

No declares que el proyecto está completamente probado si no has ejecutado las pruebas correspondientes.
