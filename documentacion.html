1. Estructura del proyecto

Es un proyecto Django con una sola app (core) y todo el contenido del sitio centralizado en core/data.py — no hay modelos ni CMS, así que para cambiar textos, precios o proyectos del portafolio se edita ese archivo directamente.

sruedadev/ ├── manage.py ├── requirements.txt ├── .env ← no versionado, se crea en cada entorno ├── .env.example ├── db.sqlite3 ├── srueda/ ← paquete de configuración Django │ ├── settings.py │ ├── urls.py │ └── wsgi.py └── core/ ← la app ├── views.py (home, portafolio_detalle, servicio_detalle, contacto...) ├── data.py ← SERVICIOS, PROYECTOS, PLANES, FAQ, contacto, WhatsApp... ├── urls.py ├── context_processors.py ├── templates/core/ │ ├── base.html │ └── partials/_*.html (navbar, hero, portafolio, contacto, footer...) ├── static/core/{css,js,img}/ └── portafolio_pages/ (una página HTML por proyecto del portafolio)

2. Instalación y ejecución en local

Terminal — en la carpeta del proyecto
python -m venv env
env\Scripts\activate        # Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver

El sitio queda disponible en http://127.0.0.1:8000/. Si no existe un archivo .env, el proyecto arranca igual con valores de desarrollo por defecto (ver siguiente sección).

5. Dónde editar el contenido del sitio

  • Textos, precios, servicios, FAQ, testimonios, portafolio: todo vive en core/data.py como diccionarios Python. No hay base de datos de por medio para este contenido.
  • Datos de contacto (correo, WhatsApp, horario, ubicación): core/data.py (WHATSAPP_NUMERO, WHATSAPP_TEXTO) y los partials core/templates/core/partials/_contacto.html y _footer.html.
  • Estilos: core/static/core/css/estilo.css — variables de color y tipografía al inicio del archivo, en :root.
  • Secciones de la página de inicio: cada bloque es un partial independiente en core/templates/core/partials/_*.html, incluido desde core/templates/core/index.html.

6. Flujo de despliegue en producción

El despliegue completo (crear la instancia EC2, Apache2 + mod_wsgi, SSL con Certbot, Route 53) está documentado aparte, paso a paso, porque son pasos de consola de AWS además de terminal. Resumen de la arquitectura:

  • Instancia EC2 (Ubuntu 22.04, t2.micro/t3.micro) con IP elástica fija.
  • El servidor clona el código directamente de GitHub (git clone / git pull), no se sube por FTP ni se copian archivos a mano.
  • Apache2 con mod_wsgi sirve la app Django; /static/ lo sirve Apache directamente desde staticfiles/.
  • Route 53 apunta sruedadev.com y www.sruedadev.com (registros tipo A) a la IP elástica.
  • Certbot (Let's Encrypt) emite y renueva el certificado SSL automáticamente.
Guía completa

Los 16 pasos detallados de consola de AWS, SSH y configuración de Apache están en la guía de despliegue publicada por separado (artifact "Despliegue sruedadev.com"), pensada para seguirse en el navegador mientras trabajas en la terminal.

7. Cómo subir cambios al sitio ya desplegado

Local
git add -A
git commit -m "Describe el cambio"
git push origin master
Servidor — SSH
cd ~/sruedadev
git pull origin master
source env/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
deactivate
sudo systemctl restart apache2

Si el cambio fue solo en plantillas, CSS o data.py (sin tocar dependencias), puedes saltarte pip install y migrate — pero collectstatic y el reinicio de Apache son necesarios siempre para que el cambio se vea reflejado.
